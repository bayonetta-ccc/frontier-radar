# 个人前沿情报雷达 · 产品需求（V3）

> 本文是项目立项时的产品定义。实现与文档以仓库代码为准；两者出现分歧时，
> 以 `README.md` 与 `docs/ARCHITECTURE.md` 描述的行为为准。

## 一、产品概述

**个人前沿情报雷达**是一款围绕用户具体目标，持续追踪高可信信息、识别关键变化，并将信息转化为证据化判断与行动线索的个人情报工具。

它真正要回答的不是“网上有什么”，而是五个问题：

1. 最近发生了什么？
2. 哪些是有实质意义的前沿信号，哪些只是营销噪声？
3. 谁在推动这些变化？
4. 结论的证据在哪里，哪些内容仍不能确认？
5. 这些变化与我的职业、目标或当前决策有什么关系？

它不以生成新闻摘要为终点，而是帮助用户建立并持续更新一套**有证据、有边界、可追溯的个人判断体系**。

一句话产品定义：

> **围绕用户的具体目标，持续监测可说明范围的高可信来源，把新信息转化为有证据、有边界的事实与判断，只推送关键变化，并说明它对用户意味着什么、下一步该验证什么。**

## 二、要解决的核心问题

面对快速发展的技术、产业与职业环境，用户通常不是完全没有信息，而是面临四个更具体的问题：

- **信息过载**：同一事件被大量转载，真正的新变化反而被淹没；
- **证据断裂**：摘要给出了结论，却无法快速回到原始来源和关键表述；
- **阶段混淆**：论文结果、实验室样品、中试、客户验证和量产计划被混为一谈；
- **缺乏连续性**：每次搜索都从零开始，无法回答“相较过去到底变了什么”。

因此，产品价值不只是节省搜索时间，而是降低用户从信息到判断的成本：

> **少翻网页、少读重复内容、少被热度误导，同时更清楚自己应该关注什么、验证什么，以及何时需要调整原有判断。**

## 三、把“最新”“重要”和“前沿”分开

### 1. 最新

指在明确时间窗口内出现的新信息。但“最新”只说明发布时间或事件发生时间较新，不代表内容重要，也不代表其中包含实质进展。

### 2. 重要

指信息可能改变用户当前关心的技术、商业、政策、职业或竞争约束。例如：

- 改变技术可行性或成本预期；
- 改变商业化、量产或采用时间；
- 改变头部主体的资源投入；
- 改变岗位能力要求；
- 改变监管、标准或市场边界。

### 3. 前沿

前沿不是单纯的热度，也不是系统随意贴上的标签，而是可能改变原有方向或竞争逻辑的信号，例如：

- 新论文、新标准、新专利；
- 开源项目的大版本或关键架构变化；
- 头部实验室或企业的路线调整；
- 关键岗位招聘所反映的技能变化；
- 监管草案、供应链扩产、客户验证；
- 对原有判断形成加强、削弱或证伪的新证据。

## 四、产品边界与基本原则

产品不承诺：

- 覆盖全网所有信息；
- 自动、绝对地区分所有前沿与噪声；
- 用热度代替重要性；
- 把官方表述等同于独立验证；
- 生成看起来完整、实际上未经核验的结论；
- 在证据不足时给出确定性的行动判断。

五项原则：

1. **覆盖透明**：明确告诉用户本次检索了哪些来源、采用了什么时间范围、哪些信息可能没有被覆盖。
2. **证据分级**：区分原始来源、转载来源、独立印证、相反证据和证据缺口。
3. **事实与判断分离**：事实、公司口径、分析推断、行业观点和未证实传闻分别呈现。
4. **变化优先**：持续追踪的重点不是重复摘要，而是识别判断发生了什么变化。
5. **相关性优先**：只保留可能影响用户目标的内容；允许系统在本期没有实质变化时明确不推送。

## 五、从“输入一个主题”升级为“主题＋目标＋决策”

任务由四部分组成：

1. **关注主题**：例如固态电池、AI Agent 协议、量化研究、人形机器人供应链。
2. **身份与目的**：学习了解、求职转型、产品与技术选型、产业研究、投资研究。
3. **当前要解决的问题**：这是筛选信息、评价重要性和生成行动建议的核心依据。
4. **决策时间范围与关键约束**：什么时间内作出判断；当前最关注性能、成本、风险、生态还是学习投入；什么新信号出现后会重新评估。

MVP 不要求复杂画像，一句自然语言即可：

> “我是谁，我想用这个主题做什么判断，我最关心什么约束，以及需要在多久之内作出决定。”

## 六、重要性与置信度评价

分别评价五个维度：

1. **新颖性**：相较已有状态是否出现实质变化，还是旧闻重提、计划重申；
2. **证据强度**：是否存在原始证据、独立印证、反向证据或复现结果；
3. **潜在影响**：可能改变什么技术、商业、政策或职业约束；
4. **用户相关性**：是否影响用户当前要做的具体判断；
5. **时效性**：区分实际事件时间、来源发布时间和未来计划时间。

三种置信度分开：

- **来源可信度**：信息来自哪里，是否为原始来源；
- **事实置信度**：所声称的事情有多大把握真实；
- **影响判断置信度**：即使事实成立，其潜在影响有多大把握成立。

例如，一家公司正式宣布建设试点产线，可以确认“公司作出了这一宣布”，但不能据此直接确认“技术已经成熟”或“一定按期量产”。

系统最终需要解释的不是一个抽象分数，而是：

> **为什么这条信息进入本期更新，而另一条热门信息被认为没有实质变化。**

## 七、主张级证据卡片

每张证据卡片围绕一个可以核验的核心主张，包含十项：

1. 核心主张（限定主体、对象和阶段）；
2. 信息分层；
3. 时间、主体与对象；
4. 原始表述与系统解读（明确哪些不能从原文推出）；
5. 证据链（原始链接、关键摘录、独立印证、同源识别、相反证据、覆盖缺口）；
6. 阶段与边界；
7. 相较过去发生了什么变化；
8. 为什么重要；
9. 与我何干（具体含义、下一步观察指标、适用条件）；
10. 置信度与待验证问题。

## 八、判断状态库：持续追踪的核心

系统保存当前领域的关键判断，例如：

- 某技术路线仍处于验证阶段；
- 某公司计划在某一时间节点进入量产；
- 某类技能正在从加分项变成岗位要求；
- 某项标准仍未形成统一路线。

这些判断是有证据、有置信度、有更新时间的**当前状态**。

### 1. 首次追踪：建立初始基线

- 根据当前任务整理 3—5 个关键判断；
- 为每个判断附上主要证据、相反证据和待验证问题；
- 明确这是当前证据下的阶段性判断；
- MVP 阶段由用户确认初始判断，避免系统在错误基线上自动迭代。

### 2. 后续更新：只识别关键变化

- **新增**：出现过去没有的重要信号；
- **增强**：旧判断获得更多独立证据；
- **削弱**：出现延期、失败、复现问题或反向证据；
- **证伪**：旧说法被足够可靠的材料否定；
- **转向**：主体改变路线、目标或时间表；
- **无实质变化**：热度很高，但底层事实没有更新。

“增强”“削弱”和“证伪”采用不同证据门槛，不因单一报道自动修改判断。

### 3. 版本、纠错与回滚

每次判断变化保留：修改前后表述、修改时间、触发证据、修改理由、用户纠错。
如果后续证据表明修改不成立，可以回到此前版本并说明回滚原因。

### 4. 本期无实质变化

如果没有足够重要的新信息，系统直接输出“本期无需更新；当前关键判断未发生变化，仍需观察以下指标”。
“敢不推送”本身就是去噪能力的一部分。

## 九、来源与持续监测机制

MVP 采用**固定核心来源＋临时补充检索**：

- 固定核心来源：官方公告与监管文件、论文/专利/标准、开源代码仓与版本记录、公司公告/产品文档/招聘信息、有明确原始出处的专业媒体；
- 临时补充检索：发现新主体、新事件和反向证据；临时来源不会仅因被检索到就自动升级为高可信来源；
- 来源管理：记录来源类型与更新频率、最近成功获取时间、失效情况、用户主动增加/排除的来源、本次结论的覆盖范围与缺口；
- 高风险或高影响结论，在证据不足时不做完全无人审核的确定性输出。

## 十、输出与可视化设计

第一版只保留四种直接回答问题的视图：

1. **变化摘要**：最近真正变了什么；哪些判断被加强或削弱；哪些热门信息可暂时忽略；哪些问题仍缺乏证据。
2. **关键时间线**：只展示关键节点，区分实际事件、官方计划、第三方预测、系统推断。
3. **证据卡片**：默认层（发生了什么变化 / 为什么与我相关 / 当前能确认到什么程度 / 下一步观察什么）＋展开层（原文摘录与链接 / 独立来源与相反证据 / 原始表述与系统推断 / 历史判断与修改记录 / 覆盖缺口与待验证问题）。
4. **与我相关面板**：我应该关注什么；暂时不需要关注什么；下一步可以做什么；哪些指标出现后需要重新评估。

主题聚类先作为技术、商业、政策、人才、资本、开源等简单筛选标签。关系图、热度×重要性矩阵和分歧地图放到后续版本。

## 十一、完整使用流程

1. 用户输入关注主题、身份目的、当前决策及关键约束；
2. 系统展示拟监测的来源范围、时间范围和覆盖限制；
3. 首次生成领域基线与 3—5 个关键判断；
4. 用户确认、修改或删除初始判断；
5. 系统按设定频率监测新增信息；
6. 对同一事件去重，区分原始报道与转载；
7. 将新证据映射到已有判断，识别新增、增强、削弱、证伪或转向；
8. 只输出高价值变化，并说明与用户需求的关系；
9. 用户标记“有用”“无关”“事实有误”“证据不足”或“变化分类有误”；
10. 系统更新关注清单和判断状态，进入下一轮追踪。

## 十二、MVP 范围

选择一个领域 × 一类用户 × 一个具体决策，例如：

- 固态电池 × 产业研究者 × 跟踪技术路线与量产节点；
- AI Agent 协议 × 产品经理 × 判断技术栈与生态变化；
- 量化研究 × 求职者 × 跟踪论文、工具和岗位技能变化。

MVP 功能：一个主题/目标/决策/约束输入；一组公开可说明的核心来源；首次基线报告与 3—5 个关键判断；
每次输出 5—8 条高价值变化（无变化允许不推送）；7 天关键时间线；主张级证据卡片；
事实/推断/观点/传闻分层；判断状态及历史版本；“与我何干”及下一步观察指标；用户反馈与纠错；
订阅“变化更新”而不是普通新闻周报。

暂时不做：全网覆盖、自动知识图谱、复杂前沿评分、多人协作、六种可视化全部上线、
完全无人审核的高风险结论、为追求更新频率而制造低价值提醒。

## 十三、验证方案与指标

连续运行 3—4 期，验证信息质量、变化识别和长期价值：

- **信息质量**：重复率与无关率；原文链接与核心主张一致率；旧闻新炒和同源多报比例；事实/推断/传闻分层；是否主动呈现不确定性、相反证据与覆盖缺口；能否快速核验关键结论。
- **判断更新质量**：新增/增强/削弱/证伪/转向是否有足够证据；是否因单一来源或营销表述过度修改判断；是否保留历史版本和修改理由；用户纠错后能否更新或回滚；无实质变化时是否仍强行生成更新。
- **用户价值**：是否发现原本会漏掉的重要变化；是否收藏、追问或查看原始证据；“与我何干”是否足够具体；是否帮助修改某个判断或行动计划；是否减少自行搜索和筛选的时间。
- **长期留存**：是否持续维护关注主题；是否愿意回来看“相较上次发生了什么变化”；减少无效推送后是否仍保持订阅；是否愿意把后续跟踪任务交给系统。

最关键的验证问题：

> **用户是否愿意让系统长期保存并更新自己的关注清单和关键判断？**

如果答案是否定的，它仍只是一个临时搜索工具；如果答案是肯定的，它才开始具备“个人情报资产”的属性。

## 十四、后续演进方向

1. 多主题并行追踪；
2. 公司—人物—技术—产品—供应链—监管关系图；
3. 技术路线与行业观点的分歧地图；
4. 热度与重要性的对照分析；
5. 用户自定义证据门槛和推送条件；
6. 跨主题关联（技术变化对岗位技能或供应链的传导）；
7. 团队协作与共享情报空间。

共同前提仍是底层的事件去重、证据映射和判断更新足够可靠。

## 十五、产品长期价值

壁垒不是搜索范围、摘要能力或可视化界面，而是长期积累的四类资产：

- 用户真正关心的主题、目标与决策约束；
- 结构化的事件、证据与来源关系；
- 关键判断的历史版本及变化原因；
- 用户对信息价值、相关性和判断错误的持续反馈。

最终交付的不是更多资讯，而是一种更可靠的个人认知更新机制：

> **少而准、有据可查、知道边界、持续更新，并始终与用户的真实目标相关。**
